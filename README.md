# 👥 Социальная Сеть (Учебный Проект)

**Социальная сеть** — это клиент-серверное Android-приложение, разработанное в учебных целях для глубокого освоения CRUD-операций, работы с локальной базой данных и архитектурных компонентов для работы с серверной частью. 

Главная техническая ценность проекта — реализация **полноценного офлайн-режима**, при котором приложение кэширует данные из сети и остается полностью работоспособным без интернета.

---

## 🛠 Технический стек и архитектура

Проект реализован на классическом, коммерчески востребованном стеке для поддержки и развития крупных Android-приложений:

- UI & Navigation: Fragments, XML-разметка, связь экранов и списков через RecyclerView.Adapter.
- Architecture: MVVM с четким разделением ответственности.
- Dependency Injection: Dagger Hilt (управление жизненным циклом зависимостей).
- Local Data & Caching: Room DB, DAO, Shared Preferences (для хранения сессии пользователя).
- Network & Paging: Retrofit, Paging 3 с использованием Remote Mediator для синхронизации сети и БД.

---

## 🚀 Возможности приложения

- Авторизация: полноценная регистрация и аутентификация пользователей на учебном сервере.
- Лента постов: динамическая подгрузка публикаций с бэкенда, просмотр детальной информации о посте.
- Полный цикл CRUD: создание, редактирование, удаление и шеринг публикаций с мгновенной синхронизацией локальной БД и сервера.

---

## 📈 Технические вызовы и полученный опыт

- Сетевое кэширование и пагинация (Remote Mediator): Одним из самых сложных этапов была настройка `Remote Mediator` для совместной работы `Paging 3`, `Retrofit` и `Room`. Освоил концепцию взаимодействия, когда UI подписывается исключительно на базу данных, а сеть лишь наполняет её. Разобрался с обработкой ошибок сети при пагинации.

- Проектирование Dependency Injection:** Столкнулся со строгими требованиями `Dagger Hilt` к конфигурации графа зависимостей. Прошел через этап сложной отладки ошибок компиляции, благодаря чему разобрался в аннотациях (`@Provides`, `@Inject`, `@HiltViewModel`) и механизме внедрения зависимостей в компоненты с разным жизненным циклом (`Activity`, `Fragment`, `Repository`).

- Управление UI на компонентах View (XML): Реализовал сложную логику взаимодействия между списком постов и экраном детального просмотра. Получил опыт работы с `RecyclerView.Adapter`, безопасной передачей данных между фрагментами и управлением состоянием экранов.

- Рефакторинг и гибкость кода: По мере усложнения проекта и добавления новых библиотек (базы данных, DI), проект неоднократно перестраивался. Это дало критически важный опыт рефакторинга и понимание того, почему жесткие связи между классами усложняют разработку, и как разделение на слои упрощает масштабирование приложения.
